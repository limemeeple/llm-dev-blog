## 전자정부 프레임워크로 AI를 넣은 ERP 시스템 구현해보기
이전에 EPR 개발을 해오면서 사용자가 사용하기 불편하다고 하는 부분들이 많이 있었다.
AI를 사용한 프로젝트를 하던 중 자연어 입력으로 시스템을 사용할 수 있다면 사용자의 적응이 더 쉽지 않을까? 라는 생각을 하게 되었다.
그래서 간단한 ERP를 만들어 AI 기능을 적용해 보기로 했다.

### 만들 범위
내가 ERP 개발을 할때 맡은 분야는 인사/총무/급여 파트였고 메뉴를 전부 합치면 30~40개는 넘어 갈것이다.
짧은 시간에 전부 만든다는건 불가능했고 선택과 집중을 하기로 했다.

[프론트(사용자용)]
인사 : 나의 인사 정보, 휴가 신청/관리
총무 : 출장 신청/관리, 배차 관리, 회의실 예약

[백오피스(관리자용)]
인사 : 인사정보 관리, 휴가 정보 관리
총무 : 출장정보 관리, 배차관리, 회의실 관리

급여의 경우에는 '급여계산' 기능이 메인인데 급여표, 세율표, 급여계산용 프로시져 부분까지 구현하는데 시간이 오래 걸릴것으로 판단하여 제외하였다.

그리고 내가 지금 진행하고 싶은 목표는 사용자의 '자연어 기능 사용'과 '엑셀 문서 자동 매핑' 기능이기 때문에 급여가 없어도 해 볼 수 있다고 생각 했다.

### DB는 MySQL
제일 많이 썼던 DB는 당연 오라클이지만 라이선스 때문에 제외하였고 PostgreSQL과 MySQL 중에 MySQL을 선택하였다.

PostgreSQL은 예약 시간 겹을 DB제약(EXCLUDE)으로 원천 차단할 수 있기때문에 회의실, 배차 예약이 있는 프로젝트와 잘 맞는다고 하지만 MySQL을 사용한 이유는 **생태계** 때문이었다.

유지보수 및 개발을 할때 국내 기관에서 오픈소스로 넘어올 때 MySQL 계열을 택한 곳이 많았었고 인터넷에 정보가 많기 때문에 막혔을 때 풀기도 좋기 때문이다.

### 프레임워크 버전은 4.3(5.0 아님)
최신인 5.0의 경우 SpringBoot3.5/JDK 17+/Jakarta 네임스페이스 기반으로 더 좋았지만 출시일이 얼마 되지 않아 자료가 많이 없었다.

그래서 한단계 바로 아래인 4.3을 선택하여 사용하기로 했다.
그리고 유지보수 진행했던 곳들은 대 부분은 4.X대 프레임 워크를 사용하고 있었기 때문에 후에 유지보수 프로젝트에 들어갔을 때 더 효용성이 있지 않을까 싶었다.

한가지 문제는 Spring AI가 Boot3.2+를 요구해서 4.3에서는 사용할 수 없다.

방법을 확인해 보니 내가 직접 HTTP 요청을 만들어서 보내는 방법이 있다고 하여 해당 방법을 사용하기로 했다. 
대신 인터페이스로 감싸는 방식을 사용하여 후에 SpringBoot3으로 업그레이드 할때 한곳만 수정하도록 하였다.

[확정된 스택]
|항목|값|
|---|---|
|프레임워크|eGovFrame 4.3|
|SpringBoot| 2.7.18
|JDK|17|
|Tomcat|9.0.x(javax)|
|ORM|MyBatis|

### 패키지 구조 : 기능 폴더 안에 계층이 들어가게 설계
AI 프로젝트를 할때 제일 난감한건 패키지 구조가 너무 중구난방이라는 것이었다.
그래서 이번에는 패키지 구조를 잡아주고 가기로 했다.
```
egovframework/
├── com/                  전자정부 공통컴포넌트 (수정 금지)
├── cmn/                  내가 만드는 공통
│   ├── vo/
│   ├── code/  file/  config/
│
├── hrm/                  [대분류] 인사
│   ├── vo/               ★ 대분류가 VO를 소유, 여러 기능이 공유
│   ├── emp/              [기능] 사원
│   │   ├── EgovEmpController.java
│   │   ├── service/          EmpService.java (공개 API)
│   │   └── serviceimpl/      EmpServiceImpl.java, EmpMapper.java
│   ├── hst/  vac/
│
├── gen/                  총무 (trp/ car/ room/)
├── apv/                  결재 공통
└── sch/                  스케줄러
```

### 환경설정과 테스트
개발에 필요한 것들을 설치하고 마지막에 간단한 예제를 통해 정상적으로 동작하는지 까지 확인하였다.

그중에 SVN만을 eclipse와 연결하여 사용하다가 Git연결을 해보게 되어 그 과정을 남긴다.

[용어 대응표]
|svn|git|
|---|---|
|checkout(최초)|clone|
|update|pull|
|commit|commit + push (2단계)
| - |staging(커밋할 것 고르는 단계, SVN엔 없다.)

1. 서버 없이 내 PC에만 버전 관리 걸어보기

- **프로젝트 우클릭 -> Team -> ShareProject -> Git -> Create**
- Repository name 작성.
- "Use or create repository in parent folder"체크하면 프로젝트 폴더 안에 .git이 생긴다.

2. .gitignore 먼저 작성한다.
커밋하기 전에 제외 목록부터 만들어야 한다. 안그러면 빌드가 통째로 올라가기 때문이다.
프로젝트 루트에 '.gitgnore'파일을 만들어 아래와 같이 작성하였다.
```
target/
.settings/
.classpath
.project
bin/
*.class
.factorypath
```

3. 첫 commit
- **프로젝트 우클릭 -> Team -> Commit**
- Git Staging 뷰가 열리는데 여기서 올릴 파일들을 선정 할 수 있다.
- UnstagedChages : 변경됐지만 커밋 대상 아직 아님.
- StagedChages : 이번 커밋에 포함할 것

Unstaged에 있는 파일들을 '+' 버튼으로 Staged로 올릴 수 있다.
.gitignore가 잘 먹혔다면 target/은 목록에 보이지 않을 거다.

- CommitMessage에 커밋 내용을 작성한다.
- Commit 버튼(Commit and Pust 누르는거 아님)

파일 아이콘이 노란 통 모양으로 바뀌면 버전관리가 시작된 거다.

4. GitHub 연결
- New repository 생성.
- Create -> 보여지는 주소 복사.
- Eclipse 에서 : **프로젝트 우클릭 -> Team -> Remote -> Push...
- URI에 복사한 주소 넣기
- Authentication : User: GitHub 아이디, Password : 비밀번호
**여기서 주의할 점은 비밀번호가 GitHub 비밀번호가 아니다.**
GitHub는 2021년부터 계정 비밀번호 push를 못하게 막았다고 한다.
대신 토큰을 쓰는데 토큰을 받는 방법은 아래와 같다.
- GitHub -> 우상단 프로필 -> Settings -> 맨 아래 Developersettings
- Personal access tokens -> Tokens(classic) -> Generate new token(classic)
- Note:작성해준다.
- 권한은 repo 체크
- Generate -> 토큰 문자열 복사(화면 벗어나면 다시 못보니 백업 필수)
- Eclipse Push 창의 Password 자리에 붙여넣기
'Store in Secure Store'에 체크하면 다음부터는 물어보지 않는다.

### 인사 테이블 생성.
ERP에 가장 기초가 되는 인사 정보에 대한 테이블을 만들기로 했다.

- emp_mst : 인사정보
- emp_hist : 인사발령이력
- emp_dept : 부서마스터

부서, 직급, 직책의 경우 바뀔 수 있기 때문에 분리하였고 기간을 넣을 수 있게 설계하였다.

### AI를 넣을 부분.
이 프로젝트는 ERP를 만든게 아니라 AI를 적용하는게 중요하다.

일단 목표는 두가지로 줄였다.
1. 채팅으로 신청과 등록을 한다.(자연어 -> 신청서)
사용자가 자연어를 사용하여 채팅창에 휴가신청, 회의 신청등을 하게 만든다.
(ex> 이번 주 화요일에 휴가 신청해줘)

2. 자연어로 데이터 추출(자연어 -> 엑셀)
자연어로 원하는 항목만, 원하는 방식으로 묶어 엑셀을 받는 기능 만든다.
POI로 고정 양식만 뽑던 방식의 한계를 넘어보는게 목적이다.

이 부분에 대해 AI와 이야기하는 과정에서 'LLM에게 권한을 주지 않는 구조'로 가야한다고 하는데 그 부분이 아직 머리에 그려지지 않는다.
(내 생각은 권한을 제한한다고 하면 AI 사용이 거의 없는거 아닌가? 라는 생각이 든다.)
이 부분은 만들다 보면 자연스레 알게될 거 같다.

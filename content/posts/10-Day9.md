## 화면방식 변경 작업 진행.
인사 조회를 만들고 화면을 만들어야 하는 상황에서 AI가 'thymeleaf'를 추천하는걸 봤다. 지금까지 작업해 오면서 'JSP'로만 화면을 만들던 나는 이 부분에 대해 주위 사람들과 수업을 해주시는 강사분의 조언을 구했다.
하지만 지금 현재 대부분이 'React'나 'Vue'로 화면을 구성한다는 조언이 많았고 이에 'React'를 가지고 화면을 만들기로 했다.

### React vs Vue
- React
  - 장점 : 생태계가 압도적으로 큼. 복잡한 화면*상태관리에 강함.
  - 단점 : 러닝커브(쉽게 시작할 수 있지만 마스터하기 어려움)가 가파르다.
- Vue
  - 장점 : 배우기 쉬움. 템플릿 문법이 HTML에 가깝고, 공식 문서가 친절함.
  - 단점 : React보다 생태계*구인 수요가 작음.

일단 많이 쓰이는게 자료도 찾기 쉽기 때문에 'React'로 결정하였다.

### 서버 렌더링 vs 프로트/백 분리
[기본(thymeleaf, 서버랜더링)]
```
브라우저 <- HTML 완성본 <- thymeleaf <- Controller <- Service <- DB
```
[전환 후(React, 분리)]
```
[프론트 프로젝트]  React  ←→  REST API(JSON)  ←→  [백 프로젝트] 전자정부
     Node.js, :5173                                    Spring Boot, :8080
```
- 전환하면서 생기는 변화.
  1. 모든 Controller가 **@RestController**가 된다. 화면(HTML)이 아니라 데이터(JSON)만 반환한다. 
  2. 프로젝트가 둘로 나뉜다. 백엔드(Spring)와 프론트(Node.js)를 각각 실행한다.
  3. CORS설정이 필요해진다. 포트가 다른 두 서버가 통신하려면 백엔드가 프론트를 허용해줘야한다.

### 지금까지 만든 내용에 대한 영향도
아직 많은걸 만들지 않았지만 지금까지 만든거에 대한 영향도 또한 생각하지 않으면 안 됐다.

|항목|전환영향|
|---|---|
|VO, Mapper, XML, Service|	영향 없다고 판단.|
|테이블 설계, 시점 조회 쿼리|	영향 없다고 판단.|
|Controller	|이미 @RestController라 영향 없다고 판단.|
|CORS 설정|	신규 추가 (설정 클래스 1개)|

문제는 로그인/세션 문제였다. 토큰(JWT)방식이 있다고 하여 후에 확인하고 도전해볼 생각이다.

다행히 거의 대부분의 소스가 그대로 사용되는걸 확인하여 진행하였다.

### CORS
프론트(:5173)와 백(:8080)은 포트가 다르다. 브라우저는 이를 다른 출처간 요청으로 보고 기본적으로 막는다고 한다. 그래서 백엔드에 해당 프론트에서 오는 요청은 허용한다고 설정해 줘야 한다.
```
package egovframework.comm.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("http://localhost:5173") // React 개발 서버
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
```
이 설정 없이 React에서 API를 부르면 콘솔에 CORS 에러가 뜬다.

### API 통신을 한곳에서 관리하기
화면마다 'fetch(http://localhost:8080/emp/list')처럼 주소를 직접 넣으면 주소가 바뀔 때 파일마다 고쳐야 할것이다. 그래서 이걸 공통 계층으로 분리 했다.

#### 환경변수로 주소 관리(.env)
```
VITE_API_BASE=http://localhost:8080
```

#### 공통 통신 함수(clent.js)
```
const API_BASE = import.meta.env.VITE_API_BASE || 'http://localhost:8080';

export async function apiGet(path) {
  const res = await fetch(`${API_BASE}${path}`, {
    headers: { 'Content-Type': 'application/json' },
    // 나중에 인증 붙일 때, 이 곳에만 토큰을 추가하면 
    // 모든 요청에 자동으로 적용 :
    // 'Authorization': `Bearer ${localStorage.getItem('token')}`
  });
  if (!res.ok) throw new Error(`API 오류: ${res.status}`);
  return res.json();
}

export async function apiPost(path, body) {
  const res = await fetch(`${API_BASE}${path}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
  if (!res.ok) throw new Error(`API 오류: ${res.status}`);
  return res.json();
}
```
#### React 폴더 구조
저번에도 이야기 했지만 바이브 코딩을 하다보면 구조가 굉장히 어지럽게 되는경향이 있었다.
그래서 이번에도 폴더 구조를 잡고 시작하기로 했다.
[계층 대응표]
|백엔드|프론트|역할|
|---|---|---|
|대분류 패키지 (emp, gen)|features/ 폴더|도메인별 분리|
|Controller|pages/ (화면)|조립·진입점|
|Service|hooks/ (로직)|비즈니스 로직|
|Mapper / API 호출|api/|데이터 가져오기|
|VO|각 api 파일 / types/|데이터 모양|
|공통(comm)|shared/|공용|

[폴더 구조 시각화]
```
src/
├── api/                    # 백엔드 통신 (Mapper 계층)
│   ├── client.js           #   공통 fetch (주소·토큰·에러 한곳)
│   └── empApi.js           #   사원 관련 API 모음
│

│   ├── emp/                #   인사

│   │   └── hooks/          #     로직 (useEmpList.js)
│   ├── gen/                #   총무

├── shared/                 # 공통 (백엔드 comm)
```

원칙은 다음과 같다.
1. 도메일 별로 폴더 처리.
2. 역할별로 분리.
3. 공통은 shared에 적용.

### 실제코드 
1. 통신계층(api/empApi.js) = 백엔드 Mapper에 해당한다.
```
import { apiGet } from './client';

export function getEmpList(params = {}) {
  const query = new URLSearchParams(params).toString();
  return apiGet(`/emp/list${query ? '?' + query : ''}`);
}
```
2. 로직계층(features/emp/hooks/useEmpList.js) = 백엔드에 Service에 해당한다.
```
import { useState, useEffect } from 'react';
import { getEmpList } from '../../../api/empApi';

export function useEmpList() {
  const [empList, setEmpList] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    getEmpList()
      .then((data) => setEmpList(data))
      .catch((err) => setError(err.message))
      .finally(() => setLoading(false));
  }, []);

  return { empList, loading, error };
}
```
#### 훅(Hook)
React에서 **use로 시작하는 함수**를 훅이라고 부른다.
- useState - 값을 저장하고, 바뀌면 화면을 자동으로 다시 그려주는 상자.
- useEffect - 화면이 처음 뜰 때(또는 특정 값이 바뀔 때) 코드를 실행.

위는 React가 만들어준 훅이다.
직접 만든 훅(useEmpList)은 커스텀 훅(custom hook) 이라고 한다.

#### 훅을 왜 만들까?
커스텀 훅 없이 화면에 로직을 다 넣으면 아래와 같아진다.
```
function EmpListPage() {
  // ▼ 여기부터 로직 (데이터 불러오기)
  const [empList, setEmpList] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    getEmpList()
      .then((data) => setEmpList(data))
      .catch((err) => setError(err.message))
      .finally(() => setLoading(false));
  }, []);
  // ▲ 여기까지 로직

  // ▼ 여기부터 화면
  if (loading) return <div>불러오는 중...</div>;
  return <EmpTable empList={empList} />;
  // ▲ 여기까지 화면
}
```
화면 하나 안에 '로직 + 화면'이 섞여 있게 된다. 지금은 짧지만 검색, 페이징, 정렬까지 붙게 되면 많이 불어나게 된다.(Controller 안에 SQL을 직접 넣었다고 생각해보면 된다.)

#### 커스텀 훅은 프론트의 "Service 빼내기" 다.
화면에서 로직을 빼내서 별도 파일로 만듬으로 Controller가 Serivce를 불러서 결과만 전달 하고 일은 Service가 하듯이 소스가 깔끔해진다. 
Service를 빼두면 여러 Controller에 갖다 쓸 수 있듯이 훅도 똑같다.
사원 목록(useEmpList)를 만들어 두면, 사원 목록이 필요한 어느 화면에서든 한줄로 불러올 수 있다.
```
// 인사 목록 화면
const { empList } = useEmpList();

// 대시보드에서 사원 수 표시할 때
const { empList } = useEmpList();

// 조직도 화면
const { empList } = useEmpList();
```
[정리]
| |백엔드|프론트|
|---|---|---|
|로직 담당|Service|커스텀 훅(useEmpList)|
|조립 담당|Controller|화면 (EmpListPage)|
|호출 방식|service.메서드()|use훅()|
|결과 전달|return|return|
|재사용|여러 Controller가 공유|여러 화면이 공유|
** 커스텀 훅은 "화면에서 로직을 빼낸 것"이고, 이건 백엔더 에서 "Controller에서 로직을 Service로 빼낸 것"과 완전히 같은 발상이다.

3. UI 부품(EmpTable.js) = 데이터를 받아 화면을 그리기만 한다.
```
function EmpTable({ empList }) {
  return (
    <table border="1" cellPadding="8" style={{ borderCollapse: 'collapse' }}>
      <thead>
        <tr>
          <th>사번</th><th>성명</th><th>부서</th><th>직급</th><th>재직상태</th>
        </tr>
      </thead>
      <tbody>
        {empList.map((emp) => (
          <tr key={emp.empId}>
            <td>{emp.empId}</td>
            <td>{emp.empNm}</td>
            <td>{emp.deptNm}</td>
            <td>{emp.gradeNm}</td>
            <td>{emp.empStat}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

export default EmpTable;
```
4. 화면 조립(EmpListPage.jsx) = 백엔드 Controller에 해당함.
```
import { useEmpList } from '../hooks/useEmpList';
import EmpTable from '../components/EmpTable';

function EmpListPage() {
  const { empList, loading, error } = useEmpList();

  if (loading) return <div style={{ padding: 20 }}>불러오는 중...</div>;
  if (error) return <div style={{ padding: 20, color: 'red' }}>에러: {error}</div>;

  return (
    <div style={{ padding: 20 }}>
      <h1>사원 목록</h1>
      <EmpTable empList={empList} />
    </div>
  );
}

export default EmpListPage;
```
훅으로 데이터를 받고, 부품에 넘겨 그린다.

[전체 흐름 시각화]
```
App.jsx
  └→ EmpListPage (조립, = Controller)
       ├→ useEmpList (로직, = Service)
       │    └→ empApi.getEmpList (통신, = Mapper)
       │         └→ client.apiGet (공통 통신)
       │              └→ 백엔드 /emp/list
       └→ EmpTable (UI 부품, 받아서 그리기만)
```

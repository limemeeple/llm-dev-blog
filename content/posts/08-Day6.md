## 툴 콜로 라우팅 하기
현재 만든 기능은 두가지이다.
1. 룰 어시스턴트(RAG) : 규칙 문서를 검색해 근거 기반으로 답변.
2. 덱 빌더(툴 콜) : 카드 DB를 도구로 조회.

문제는 사용자가 규칙을 물을지 덱(카드)을 물을지 알 수가 없다.
들어온 질문을 어떤 기능에게 보낼지가 라우팅 문제다.

거기서 덱 빌더를 만들때 사용한 **툴 콜**을 사용하여 두 기능을 '도구'로 감싸고 LLM이 질문을 보고 어느 '도구'를 쓸지 고르게 했다.

![alt text](../img/toolcall_img.png)
여기서 배울 점은 **조합(composition)**이다. 복잡한 서브시스템은 하나의 도구 인터페이스 뒤에 숨기고 상위 LLM은 그 인터페이스만 안다. '도구'가 단순 함수든, RAG 파이프라인 이든, 또 다른 에이전트 이든 LLM 입장에서는 똑같은 '도구'로 보는거다.

[추가 설명]
#### 작은 것들을 합쳐서 큰 것을 만들되, 큰 것이 작은 것의 내부를 몰라도 된다.
해당 내용은 '조합(composition)'의 설명이다. 각 층이 아래층을 도구로 쓰고, 위층에겐 자기가 도구가 된다. 계층이 쌓일대 각 계층은 아래 계층만 알고 있으면 된다.

이걸 지금 만들고 있는 시스템으로 설명하자면
- search_cards(함수) + get_deckbuilding_rules(함수) -> 조합 -> 덱 빌더 에이전트
- expand_query + retrieve + 생성 -> 조합 -> RAG 룰 어시던트
- 덱 빌더 에이전트 + RAG 룰 어시던트 -> 조합 -> 통합 오케스트레이터

여기서 통합 오케스트레이터는 덱 빌더가 무슨일을 하는지 룰 어시던트가 무슨일을 하는지 모른다. 다만 '이건 덱 빌더한테, 이건 룰 어시던트에게' 전달하는 방법만 아는거다.
```
#단순 함수
def get_deckbuilding_rules(investigator: str) -> str:
    return json.dumps(mock_rules.get(investigator))   # dict 조회 한 줄

#외부 API 호출
def search_cards(name: str) -> str:
    cards = _load_cards()      # ArkhamDB API 호출, 캐싱, 한글 병합...
    return json.dumps(matches)

#RAG 파이프라인
def run_ask_rules(question: str) -> str:
    result = rules_answer(question)   # 쿼리확장(LLM) → 임베딩 → 벡터검색 → 생성(LLM)
    return result["answer"]

#다른 에이전트
def run_build_deck(request: str) -> str:
    result = deck_ask(request)   # 안에서 자기만의 툴 콜 루프를 5번까지 돎!
    return result["answer"]
```
해당 코드를 보면 인터페이스가 같기 때문에 안에 시스템이 복잡하든 아니든 상관 없이 도구로서 사용할 수 있다.

#### 그럼 이렇게 설계해서 얻는 이득은 뭔데?
1. mock -> 실데이터 교체.
search_cards를 만들 때 mock 데이터로 만든 이후 ArkhamDB API 호출로 변경했을 때 에이전트 루프는 고치지 않았다. 구현을 바꿔도 나머지가 깨지지 않고 유지 된다.

2. 도구 추가가 한줄이다.
get_deckbuilding_rules를 도구로 추가했을때 'TOOLS'에 스키마 추가, 함수 구현, 'TOOL_DISPATCH'추가 할뿐 루프는 건들지 않았다. 만약 'if ... else..' 구조 였다면 거기도 고쳐야 했을거고 개수가 늘어날 수록 힘들어진다.

3. 확장에 용이하다.
예시로 '캠페인 트래커' 기능을 추가한다고 하면
```
TOOLS.append({"name": "track_campaign", "description": "..."})
TOOL_DISPATCH["track_campaign"] = run_track_campaign
```
문자열 -> 문자열만 지킨다면 오케스트레이터가 알아서 사용한다.

4. 문제를 격리해서 고칠 수 있다.
각 계층이 분리돼 있으니 문제가 생긴 층만 고치면 된다. 

5. 시스템 통째를 도구로 전환.
만약 인터페이스 통일 없이 각자 다른 방식으로 만들었다면? 오케스트레이터가 기능을 부르는 특수처리를 각가 해야했을 것이다.

한마디로 **변경의 파급을 막을 수 있다**로 정리해 볼 수 있겠다.

#### 단점은 없는건가?
물론 장점만 있는 것은 아니다.

1. 추상화 비용.
단순화 하는 대신 성능저하, 유연성 상실, 복잡한 설계로 인한 추가적인 인프라/유지보수 비용 발생.

2. 지연·비용.
중첩 에이전트라 LLM이 호출이 겹겹히 쌓여 지연과 비용이 늘어난다.

3. 디버깅의 어려움.
계층이 깊어질수록 어디서 잘못됐는지 찾기가 힘들어진다.
이 부분을 해결하기 위해 각 계층마다 print(f"→ 라우팅: ...") 로그를 심어둔다.

## 두 시스템을 도구로 감싸자
오케스트레이터를 만들어서 두 시스템을 '질문 넣으면 답나오는 함수'로 만들어 넣기로 했다.
```
import anthropic
from dotenv import load_dotenv

from src.rules.assistant import answer as rules_answer   # RAG 룰 어시스턴트
from src.deck.builder import ask as deck_ask             # 툴 콜 덱 빌더

load_dotenv()
client = anthropic.Anthropic()
MODEL = "claude-haiku-4-5-20251001"

TOOLS = [
    {
        "name": "ask_rules",
        "description": (
            "아컴호러 카드게임의 '게임 규칙·룰 판정'에 답한다. "
            "기회 공격, 단서 획득, 전투 절차, 회피, 게임 진행 순서 등 "
            "'어떻게 플레이하는가'에 대한 질문에 사용한다. "
            "특정 카드의 정보 조회가 아니라, 게임 메커니즘을 물을 때만 쓴다."
        ),
        "input_schema": {
            "type": "object",
            "properties": {"question": {"type": "string", "description": "규칙 관련 질문"}},
            "required": ["question"],
        },
    },
    {
        "name": "build_deck",
        "description": (
            "특정 카드의 정보 조회, 카드 검색, 덱 구성·추천에 답한다. "
            "'○○ 카드 정보 알려줘', '○○ 카드 찾아줘', "
            "'덱 짜줘', '무슨 카드 넣어?' 처럼 "
            "개별 카드나 덱빌딩에 관한 질문일 때 사용한다."
        ),
        "input_schema": {
            "type": "object",
            "properties": {"request": {"type": "string", "description": "덱 빌딩 요청"}},
            "required": ["request"],
        },
    },
]
```
여기서 **description**이 라우팅 로직이다. 라우터는 이 설명만을 보고 판단하기 때문에 대충썼다가는 버그가 발생한다.

## 오케스트레이터 루프
```
SYSTEM = """너는 아컴호러 카드게임 도우미야.
사용자 질문이 '규칙'에 관한 것이면 ask_rules를, '덱 구성/카드 추천'이면 build_deck를 사용해.
도구 결과를 바탕으로 한국어로 자연스럽게 답해.

[답변 스타일]
- 일관되고 차분한 존댓말로 답한다.
- 이모지를 쓰지 않는다.
- "말씀해주세요" 같은 상투적 마무리를 붙이지 않는다.
- 도구가 준 근거 안에서만 답하고, 없는 내용은 지어내지 않는다."""


def assistant(question: str) -> dict:
    messages = [{"role": "user", "content": question}]
    collected_sources = []      # 곁가지: RAG 출처
    collected_cards = []        # 곁가지: 검색된 카드(이미지 포함)

    # 안쪽 함수로 정의 → 바깥 리스트에 접근(클로저)
    def run_ask_rules(question: str) -> str:
        result = rules_answer(question)
        collected_sources.extend(result.get("sources", []))
        return result["answer"]

    def run_build_deck(request: str) -> str:
        result = deck_ask(request)                        # dict 반환
        collected_cards.extend(result.get("cards", []))   # 카드를 곁가지로
        return result["answer"]                           # LLM한텐 텍스트만

    dispatch = {"ask_rules": run_ask_rules, "build_deck": run_build_deck}

    def run_tool(block) -> str:
        fn = dispatch.get(block.name)
        if fn is None:
            return f"알 수 없는 도구: {block.name}"
        try:
            return fn(**block.input)
        except Exception as e:
            return f"{block.name} 실행 실패: {e}"

    for step in range(5):   # 무한 루프 방지
        response = client.messages.create(
            model=MODEL, max_tokens=2048, system=SYSTEM,
            tools=TOOLS, messages=messages,
        )

        if response.stop_reason != "tool_use":
            answer_text = "".join(b.text for b in response.content if b.type == "text")
            return {"answer": answer_text, "cards": collected_cards, "sources": collected_sources}

        messages.append({"role": "assistant", "content": response.content})
        tool_results = []
        for b in response.content:
            if b.type == "tool_use":
                print(f"  → 라우팅: {b.name}({b.input})")   # 어디로 갔는지 관찰
                tool_results.append({
                    "type": "tool_result", "tool_use_id": b.id,
                    "content": run_tool(b),
                })
        messages.append({"role": "user", "content": tool_results})

    return {"answer": "최대 반복 횟수를 초과했습니다.", "cards": collected_cards, "sources": collected_sources}
```
'곁가지'로 표시 데이터 빼내기
LLM이 만드는 답변 텍스트와 앱이 구조적으로 쓰는 데이터(카드 이미지, 출처)는 별개의 경로여야 한다. 구조화된 데이터를 LLM의 답변 텍스트와 섞게 되면 LLM이 왜곡 해 버릴 수 있기 때문이다.
그래서 구조화된 데이터는 'collected_cars'에 모아두고 최종 답변과 반환한다.

[코드 실행 후 로그]
```
=== 규칙 질문 ===
  → 라우팅: ask_rules({'question': '기회 공격은 언제 발생하나?'})

=== 덱 질문 ===
  → 라우팅: build_deck({'request': '롤랜드 뱅크스 덱'})
[step 0] stop_reason = tool_use
  → 도구 호출: get_deckbuilding_rules({'investigator': 'Roland Banks'})
  → 도구 호출: search_cards({'name': 'Roland Banks'})
[step 1] stop_reason = end_turn
```
에이전트 안에 에이전트가 있는 구조가 로그로 그대로 보입니다.
build_deck을 부르면, 그안에서 덱 빌더가 또 자기만의 툴 콜 루프를 돈다. 심지어는 도구 두개를 한 스템에서 병렬 호출하고 있다.
위 에서 말했듯이 이런한 점 때문에 에이전트가 겹겹히 쌓일 수록 느려지고 비싸진다.

## 라우팅 오류 발생. - description이 곧 로직이다.
테스트를 위해 한가지 카드(악을 처단하라)에 대한 정보를 달라고 질문 했다.
그런데 답변이 나오지 않아 로그를 확인해보니 'ask_rules(규칙)'으로 라우팅 되는걸 확인 했다.

원인은 'build_deck' 설명 맨 앞에 **덱 구성/추천**에만 초점이 맞춰져 있어서 였다.
'카드 정보 조회'가 어느 도구 소관인지 설명을 찾을 수 없으니 라우터가 규칙 쪽으로 흘려보낸 것이었다.

#### 해결 방법
'build_deck' 설명 맨 앞에 '특정 카드의 정보조히, 카드 검색'을 명시하고, ask_rules에는 '특정 카드 정보 조회가 아니라 게임 메커니즘'이라고 선을 그었다.
(위 코드에 있는 description가 최종 수정본이다.)

## 다국어 데이터 병합 - 한글 카드 검색 추가.
'악을 처단하라'라는 카드의 정보를 조회해 달라고 하자 카드를 찾지 못했다는 답변을 전달 받았다.
확인해보니 ArkhamDB 영어 API의 name과 겹치는게 없기 때문이 었다.
규칙 검색의 경우 의미 기반(임베딩)이라 다국어에 대한 문제를 넘어갈 수 있었지만 카드 검색은 글자 매칭이기 때문에 한국어로 영어를 검색할 수 없었다.

그런데 ArkhamDB 사이트에는 이미 한국어로 보여주는 페이지가 존재하였고 확인 해본 결과 주소 앞에 ko를 붙이면 된다는걸 확인했다.

api 주소 앞에 ko를 붙이고 검색을 하자 name이 '악을 처단하다', text가 정발 번역으로 나오는걸 확인 했다.(이미지는 영문 이미지 공통으로 사용하고 있었다.)

#### 해결방법
두 API를 카드 코드(code)로 병합했다.
```
ARKHAMDB_BASE = "https://arkhamdb.com"
ARKHAMDB_CARDS_URL = "https://arkhamdb.com/api/public/cards/"
ARKHAMDB_CARDS_URL_KO = "https://ko.arkhamdb.com/api/public/cards/"

_card_cache = None

def _load_cards() -> list:
    """영어·한글 카드를 code로 병합해서 캐시. 하나의 카드에 두 이름을 담는다."""
    global _card_cache
    if _card_cache is None:
        en = requests.get(ARKHAMDB_CARDS_URL, timeout=10)
        en.raise_for_status()
        ko = requests.get(ARKHAMDB_CARDS_URL_KO, timeout=10)
        ko.raise_for_status()

        # 한글 데이터를 code → {한글이름, 한글본문} 으로 매핑 (join 준비)
        ko_map = {
            c["code"]: {"name_ko": c.get("name", ""), "text_ko": c.get("text", "")}
            for c in ko.json() if "code" in c
        }

        merged = []
        for c in en.json():
            ko_data = ko_map.get(c.get("code"), {})
            c["name_ko"] = ko_data.get("name_ko", "")
            c["text_ko"] = ko_data.get("text_ko", "")
            merged.append(c)
        _card_cache = merged
    return _card_cache


def search_cards(name: str) -> str:
    cards = _load_cards()
    query = name.lower()

    # 영어 이름 '또는' 한글 이름에 검색어가 걸리면 매칭
    matches = [
        c for c in cards
        if query in c.get("name", "").lower()      # 영어 이름
        or query in c.get("name_ko", "").lower()   # 한글 이름
    ]

    if not matches:
        return json.dumps({"error": f"'{name}'에 해당하는 카드를 찾지 못했습니다."},
                          ensure_ascii=False)

    results = []
    for c in matches[:5]:
        imagesrc = c.get("imagesrc")
        results.append({
            "name": c.get("name"),              # 영어 이름
            "name_ko": c.get("name_ko", ""),    # 한글 이름 (화면 표시용)
            "type": c.get("type_name"),
            "faction": c.get("faction_name"),
            "xp": c.get("xp", 0),
            "text": c.get("text", ""),          # 영어 본문 (LLM 근거용)
            "text_ko": c.get("text_ko", ""),    # 한글 본문 (화면 표시용)
            "image_url": ARKHAMDB_BASE + imagesrc if imagesrc else None,
        })
    return json.dumps(results, ensure_ascii=False)
```
 - LLM에게 주는 근거는 영어 원문(text)으로 유지하고, 화면 표시용으로 한글(name_ko, text_ko)을 추가 했다. 이 작업으로 API를 두번 호출 하기 때문에 첫 로딩이 늘어나지만 _load_cards는 한 번만 실행되고 캐시하므로 실사용엔 영향이 없다.

## 검증 노트 - 기본에 없는 카드 설명에 대한 검증
한국어로 '악을 처단하라' 라는 카드 정보를 알려달라고 하자 답변을 주는걸 확인했다.
그런데 기본 카드에는 없던 답변이 추가되어 있는걸 확인했다.
그런데 내용이 너무 그럴싸해서 환각인지 아닌지 판단하기 어려웠다.
```
result = search_cards("악을 처단하라")
cards = json.loads(result)
print(f"검색된 카드 수: {len(cards)}장")
for c in cards:
    print(c.get("name"), "/", c.get("name_ko"), "| xp:", c.get("xp"))
    print(c.get("text_ko", "")[:80])
```

## FastAPI로 API 열기 — Spring Boot와 1:1 대응
```
import os
from fastapi import FastAPI, Header, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse
from pydantic import BaseModel
from typing import Any
from dotenv import load_dotenv

from src.orchestrator import assistant

load_dotenv()
app = FastAPI(title="아컴호러 어시스턴트 API")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"], allow_methods=["*"], allow_headers=["*"],
)

SECRET_KEY = os.environ["APP_SECRET_KEY"]   # 코드에 박지 말고 .env에서


class AskRequest(BaseModel):
    question: str

class AskResponse(BaseModel):
    answer: str
    cards: list[dict[str, Any]] = []        # 카드 목록 (룰 질문이면 빈 배열)


# ── API 라우트 (정적 서빙보다 먼저) ──
@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/ask", response_model=AskResponse)
def ask(req: AskRequest, x_app_key: str = Header(default="")):
    if x_app_key != SECRET_KEY:
        raise HTTPException(status_code=401, detail="접근 권한이 없습니다.")
    result = assistant(req.question)
    return AskResponse(answer=result["answer"], cards=result.get("cards", []))


# ── 정적 파일(React 빌드) 서빙 ──
app.mount("/assets", StaticFiles(directory="static/assets"), name="assets")

@app.get("/")
def serve_index():
    return FileResponse("static/index.html")

@app.get("/{filename}")      # static/ 최상단 파일 (배경 이미지 등)
def serve_static_file(filename: str):
    file_path = os.path.join("static", filename)
    if os.path.isfile(file_path):
        return FileResponse(file_path)
    raise HTTPException(status_code=404, detail="Not Found")
```
|Spring Boot|FastAPI|
|----|----|
|@SpringBootApplication|app = FastAPI()|
|@PostMapping("/ask")|@app.post("/ask")|
|@RequestBody AskRequest|req: AskRequest (Pydantic)|
|DTO + Bean Validation|class AskRequest(BaseModel) — 타입 자동 검증|
|@CrossOrigin|CORSMiddleware|
|내장 Tomcat|uvicorns|
|pringdoc/Swagger|/docs 자동 제공|

프런트 없이 'http://localhost:8000/docs'에서 바로 API 테스트를 할 수 있게 됐다.

[실행하면서 생겼던 오류 노트]
1. 405 Method Not Allowed
프런트 빌드를 백엔드가 서빙하려고 'app.mount("/", StaticFiles(...))'를 썼더니 POST /ask가 405로 막혔다.
'mount("/")'sms '/' 이하 전부를 가로채는 'StaticFiles'는 GET만 서빙하기 때문에 '/ask POST'가 GET만 돼! 라면 거부한것이다.
이건 위 아래로 코드를 이동한다고 해결되지 않는 문제였다.

#### 해결방법
mount를 '/'rk dkslfk '/assets'에만 걸고, 화면은 명시적 라우트(@app.get("/"))로 반환하게 변경하였다. 이로써 세 경로가 서로를 밟지 않게 했다.
- GET / : 화면
- GET /assets/XXX.js : JS/CSS
- POST /ask : API

2. /{filename} 라우트 순서
배경 이미지를 넣었는데 404가 발생하였다. 분명 정확한 위치에 파일은 검색 되는데 왜 배경이 안나오는지 확인해본 결과 'assets/' 밖의 최상단 파일은 서빙 라우트가 없었다.

#### 해결방법
@app.get("/{filename}")을 추가하였다.

## React 프런트 - 카드 이미지 표시하기
```
// App.jsx
import { useState } from "react";
import "./App.css";

const API_URL = "";                       // 백엔드가 같이 서빙 → 상대경로
const APP_KEY = import.meta.env.VITE_APP_KEY;

export default function App() {
  const [question, setQuestion] = useState("");
  const [answer, setAnswer] = useState("");
  const [cards, setCards] = useState([]);
  const [loading, setLoading] = useState(false);

  async function handleAsk() {
    if (!question.trim()) return;
    setLoading(true);
    setAnswer("");
    setCards([]);
    try {
      const res = await fetch(`${API_URL}/ask`, {
        method: "POST",
        headers: { "Content-Type": "application/json", "X-App-Key": APP_KEY },
        body: JSON.stringify({ question }),
      });
      const data = await res.json();
      setAnswer(data.answer);
      setCards(data.cards || []);
    } catch (e) {
      setAnswer("요청 실패: 백엔드가 켜져 있는지 확인하세요.");
    } finally {
      setLoading(false);
    }
  }

  return (
    <div className="arkham-wrap">
      <h1 className="arkham-title">Arkham Horror Assistant</h1>

      <textarea
        className="arkham-input"
        value={question}
        onChange={(e) => setQuestion(e.target.value)}
        placeholder="규칙이나 카드에 대해 물어보세요"
        rows={3}
      />
      <button className="arkham-btn" onClick={handleAsk} disabled={loading}>
        {loading ? "생각 중..." : "질문하기"}
      </button>

      {answer && <div className="arkham-answer">{answer}</div>}

      {cards.length > 0 && (
        <div className="arkham-cards">
          {cards.map((card, i) => (
            <div className="arkham-card" key={i}>
              <div className="arkham-card-left">
                <p className="arkham-card-name">{card.name_ko || card.name}</p>
                {card.image_url && (
                  <img src={card.image_url} alt={card.name_ko || card.name} />
                )}
              </div>
              <div className="arkham-card-right">
                {card.text_ko && (
                  <div dangerouslySetInnerHTML={{ __html: card.text_ko }} />
                )}
              </div>
            </div>
          ))}
        </div>
      )}
    </div>
  );
}
```
[알아둬야할 점]
- cards.map(...) : 배열을 UI 요소로 반환한다.
- dangerouslySetInnerHTML : 카드 본문에 '<b>' 태그를 실제 굵게 랜더링 한다. 
- card.name_ko || card.name : 한글 이름이 없으면 영어로 준다.
- card.image_url && : 이미지가 없는 카드도 있기 때문에 조건부 랜더링.

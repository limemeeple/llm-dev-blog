## 이렇게 개발 할 수 있다면 내 취미에도 사용해보자!

자신의 취미에 개발을 더 할 수 있다면 더 좋지 않을까? 라는 생각에 시작하게 되었다.
내 취미는 보드게임 인데 애증의 게임이 있으니 그 이름 바로 **'아캄호러카드게임!'**

큰 룰보다는 잔룰이 많은 게임이다 보니 한판 한판 할때마다 에러플레이도 많이하고
카드도 굉장히 많기 때문에 쉽게 시작할만한 게임은 아니다.

그러다 보니 나오는 시리즈만 사서 카드 정리만 할뿐 제대로 게임을 한적이 없었다.

**그. 래. 서.**

게임을 쉽게 시작할 수 있게 도와주는 덱빌딩 이나 규칙 설명을 해줄 수 있는 '아컴호러 카드게임 헬프 에이전트'를 만들기로 했다.

## 무엇이 에이전트 인가?

LLM API를 한번 호출해서 답을 받기보다는 LLM이 지금 tools가 필요한지 판단하고 도구를 부르고 그 결과를 받아서 다시 생각하는 루프를 돌게 할것이다.
```
사용자 질문 → LLM(판단) → (도구 필요?) → 도구 실행 → 결과를 LLM에 반영 → ... → 최종 답변
```
언어는 'Python'을 모델은 'Anthropic Claude API' 쓰기로 했다.

## 첫 LLM 호출과 '무상태'

앞서 개발에서도 그랬지만 '.env' 파일에 키를 넣고 '.gitignore'에 추가하였다.
잘못해서 공개 레포에 키를 올려버리면 진짜 큰 사고이기 때문이다.

[요청과 응답 해부]
```
import anthropic
from dotenv import load_dotenv

load_dotenv()
client = anthropic.Anthropic()   # 키는 환경변수에서 자동으로 읽음

message = client.messages.create(
    model="claude-haiku-4-5-20251001",   # 실험 단계엔 저렴한 모델
    max_tokens=1024,
    system="너는 아컴호러: 카드게임 규칙 전문가야. 한국어로 간결하게 답해.",
    messages=[
        {"role": "user", "content": "아컴호러 카드게임이 뭐야? 두 문장으로 설명해줘."}
    ],
)

print(message.content[0].text)   # 답 텍스트
print(message.usage)             # 토큰 사용량 (비용의 근거)
print(message.stop_reason)       # 왜 멈췄나
```
위 코드에서 알아야 할것 정리
#### [요청]
- mesages : 대화 turn을 담은 배열. 각 항목은 role(user/assistant) + content 이고 이 배열이 곧 '대화 이력'이다.
- system : 모델의 정체성-규칙을 주는 별로 파라미터. 프롬프트 엔지니어링의 시작점이다.
- max_tokens : 출력 길이의 상한(입력이 아닌점 주의)

#### [응답]
- content : 문자열이 아니라 블록의 배열. 텍스트 답은 content[0].text에 들어있다.
- stop_reason : 왜 멈췄는지 이유.
- usage : input_token / output_tokens 비용의 근거.

#### [반드시 체화할 개념 3가지]
- 무상태(stateless) : API는 기억이 없다. 이전 대화를 기억하는 게 아니라, 매 호출마다 전체 이력을 messages에 다시 실어 보내는 거다. '대화가 이어진다'는 것은 내 코드가 배열을 쌓아주기 때문이다.
- 토크과 비용 : 입력/출력이 토큰 단위로 계산되고 토큰당 과금이 된다. 컨텍스트 윈도우(한 번에 넣을 수 있는 양)에도 상한이 있다.(usge로 찍어보며 확인.) 
- 비결정성과 환각 : 같은 입력을 해도 답이 달라 질 수 있고 모르는걸 지어낼 수 있다. 이 부분이 RAG가 필요한 근본 이유이다.

[멀티턴 = 이전 대화의 맥락을 기억하고 이어 나가는 상호작용 방식]
```
messages = []
while True:
    user_input = input("나: ")
    if user_input.strip().lower() == "quit":
        break

    messages.append({"role": "user", "content": user_input})   # 내 발화 추가

    response = client.messages.create(
        model="claude-haiku-4-5-20251001",
        max_tokens=1024,
        messages=messages,          # 이력 '전체'를 통째로 보낸다 ← 무상태의 핵심
    )
    reply = response.content[0].text

    messages.append({"role": "assistant", "content": reply})   # 답변도 이력에 추가
    print(f"Claude: {reply}")
    print(f"  (input_tokens={response.usage.input_tokens})")   # 턴마다 커진다
```
append를 사용해 이력을 보내 기억하는것 처럼 보낸다. 대화가 길어질 수록 input_tokens가 계속 커진다.

## 도구를 불러 보자.

실제 데이터가 필요한 질문은 LLM 지식만으로는 부정확할 수 있다. 그래서 LLM에게 도구를 쥐여준다.

#### [도구 호출 한번의 왕복(4단계)]
1. 코드 -> API : 질문 + tools(도구 목록)를 함께 전송한다.
2. LLM 판단 : 도구를 쓰기로 하면 stop_reason = tool_use로 응답.
3. 코드 실행 : 도구를 실제로 돌리고, 결과를 이력에 넣어 재호출
4. LM 최종 답변: 결과를 보고 답을 만듦 (stop_reason = end_turn)
'뭘 부를지'는 LLM이, '어떻게 실행할지'는 코드가 담당한다.

#### [도구정의]
```
TOOLS = [
    {
        "name": "search_cards",
        "description": "아컴호러 카드를 이름으로 검색한다. 카드 정보를 물어볼 때 사용한다.",
        "input_schema": {
            "type": "object",
            "properties": {
                "name": {"type": "string", "description": "검색할 카드/조사자 이름"}
            },
            "required": ["name"],
        },
    }
]
```
'input_schema'는 JSON Schema로 쓴 메서드 시그니처 선언이다.
'description'은 LLM이 판단할 수 있게 도와주는 설명이다. 이 설명을 읽고 '이 질문에는 이 도구를 써야겠다'라고 판단한다. 설명이 부실하면 엉뚱한 도구를 쓰거나 아무 도구도 쓰지 않을 수 있으니 주의 해야하고 도구 설명 또한 프롬프트 엔지니어링이다.

#### [tool_use 응답의 실제 모양]
LLM이 도구를 쓰겠다고 하면 응답이 아래와 같이 온다.
```
{
  "role": "assistant",
  "stop_reason": "tool_use",
  "content": [
    {
      "type": "tool_use",
      "id": "toolu_01Xy...",
      "name": "search_cards",
      "input": { "name": "Roland Banks" }
    }
  ]
}
```
Python SDK로 꺼내기
```
if response.stop_reason == "tool_use":
    for block in response.content:
        if block.type == "tool_use":
            block.id      # "toolu_01Xy..." ← 결과 돌려줄 때 이 id를 매칭
            block.name    # "search_cards"
            block.input   # {"name": "Roland Banks"} ← 이미 dict, 파싱 불필요
```
[핵심 내용]
- name : 어떤 도구를 부를지 지정.
- input : 인자. 
- id : 결과를 돌려줄때 id를 그대로 붙여야 어느 호출에 대한 답인지 연결.

#### 에이전트 루프 (전체)
```
import json

# 이름 → 실제 함수 매핑 (전략 패턴)
TOOL_DISPATCH = {"search_cards": search_cards}

def run_tool(block) -> str:
    fn = TOOL_DISPATCH.get(block.name)   # 없으면 None
    if fn is None:
        return json.dumps(
            {"error": f"알 수 없는 도구: {block.name}. "
                      f"사용 가능한 도구: {list(TOOL_DISPATCH.keys())}"},
            ensure_ascii=False,
        )
    try:
        return fn(**block.input)         # dict를 키워드 인자로 언패킹
    except Exception as e:
        return json.dumps({"error": f"{block.name} 실행 실패: {e}"}, ensure_ascii=False)

def ask(question: str) -> str:
    messages = [{"role": "user", "content": question}]

    for step in range(5):   # 무한 루프 방지 (최대 5회)
        response = client.messages.create(
            model="claude-haiku-4-5-20251001",
            max_tokens=1024, tools=TOOLS, messages=messages,
        )

        if response.stop_reason != "tool_use":   # 최종 답변
            return "".join(b.text for b in response.content if b.type == "text")

        # (a) LLM 응답(tool_use 포함)을 이력에 넣는다
        messages.append({"role": "assistant", "content": response.content})

        # (b) 각 tool_use 실행 → tool_result 로 변환
        tool_results = [
            {"type": "tool_result", "tool_use_id": b.id, "content": run_tool(b)}
            for b in response.content if b.type == "tool_use"
        ]

        # (c) 결과를 user 메시지로 넣고 다시 호출 → 루프 계속
        messages.append({"role": "user", "content": tool_results})

    return "최대 반복 횟수를 초과했습니다."
```
**for step in range(5)** : LLM이 같은 도구를 계속 부르며 무한 루프에 빠질 수 있기 때문에 최대 반복 횟수(무한 루프 방지(방어 코드))로 끊어준다.

## 방어처리 - 에이전트는 죽으면 안된다.
도구 실행 중 예외가 터지면 에이전트 전체가 비정상적으로 멈출 수 있다.

방어처리의 대원칙은 
```
실패를 예외로 던져 프로그램을 죽이지 말고, 상황에 맞는 '데이터'로 변환한다. LLM이 아직 대화 중이면 그 데이터를 tool_result로 돌려주고, LLM 자체가 응답 불가면 사용자에게 알리고 종료한다.
```
이다.

에러가 터질 수 있는 지점은 성격별로 세 층이다.

1층 - 도구 실행 자체의 실패(없는 도구, 잘못된 인자, 내부 예외, 네트워크 오류) -> tool_result로 돌려주고 루프는 계속 된다.(위 코드에서 run_tool이 담당)

2층 - API 호출 자체의 실패(과부하, 레이트 리밋, 네트워크) 0> 표준대처는 지수 백오프 재시도이고, SDK가 기본내장(max_retries)한다. 그래도 실패하면 사용자에게 정중히 알리고 즉시 종료 한다.
```
try:
    response = client.messages.create(...)
except anthropic.APIError as e:
    print(f"API 호출 실패: {e}")
    return "지금 응답을 받지 못했어요. 잠시 후 다시 시도해 주세요."
```

3층 - 응답이 예상과 다른 경우(max_tokens로 잘림, refusal로 거부) -> stop_reason 별로 분기 시킨다.

```
if response.stop_reason == "max_tokens":
    return "답변이 너무 길어 잘렸어요. max_tokens를 늘려보세요."
if response.stop_reason == "refusal":
    return "이 요청에는 답변하기 어렵습니다."
```

1층은 결과를 LLM에게 돌려주고 루프를 계속하지만, 2/3층은 즉시 종료한다.(2/3층은 LLM 자체가 응답하지 못하기 때문)

#### 에러 메시지도 프로프트다.
1층 에러에 '사용 가능한 도구 목록'을 같이 넣어주면, LLM이 없는 도구를 부른 뒤 그 목록을 보고 유효한 도구를 스스로 찾아 복구를 시도한다.
이 차이가 '에러 메시지 설계'가 왜 실력인지 보여준다.(단, 항상 복구되는건 아니고 복구 시도를 할 수 있게 설계하는게 실력이다.)

## 실데이터를 연동해보자(ArkhamDB API)

mock 도구가 잘 돌아가는 걸 확인한 이후에 실제 API로 갈아끼우는 작업을 진행 했다.

#### ArkhamDB 공개 API(인증 불필요):
- GET https://arkhamdb.com/api/public/cards/ — 전체 카드를 JSON 배열로 반환
- GET https://arkhamdb.com/api/public/card/{code}.json — 카드 하나

```
import requests

ARKHAMDB_BASE = "https://arkhamdb.com"
ARKHAMDB_CARDS_URL = f"{ARKHAMDB_BASE}/api/public/cards/"

_card_cache = None

def _load_cards() -> list:
    global _card_cache
    if _card_cache is None:
        resp = requests.get(ARKHAMDB_CARDS_URL, timeout=10)   # 타임아웃 필수
        resp.raise_for_status()                               # 4xx/5xx → 예외
        _card_cache = resp.json()
    return _card_cache

def search_cards(name: str) -> str:
    cards = _load_cards()
    query = name.lower()
    matches = [c for c in cards if query in c.get("name", "").lower()]

    if not matches:
        return json.dumps({"error": f"'{name}' 카드를 찾지 못했습니다."}, ensure_ascii=False)

    results = []
    for c in matches[:5]:                       # 너무 많으면 상위 5개
        imagesrc = c.get("imagesrc")            # 없을 수도 있음
        results.append({
            "name": c.get("name"),
            "type": c.get("type_name"),
            "faction": c.get("faction_name"),
            "xp": c.get("xp", 0),
            "text": c.get("text", ""),
            "image_url": ARKHAMDB_BASE + imagesrc if imagesrc else None,
        })
    return json.dumps(results, ensure_ascii=False)
```
[핵심 정리]
- timeout = 10 : 외부 API 호출엔 항상 타임아웃을 설정해야한다. 없으면 서버 무응답시 프로그램이 영원히 멈출 수 있다.
- raise_for_status() : HTTP 에러를 예외로 바꿔서 run_tool의 방어 처리가 잡게 해준다.(ArkhamDB가 죽어도 에이전트는 안죽게 함.)
- 이미지 : imagesrc에 baseURL을 붙여 이미지를 불러오게 한다. 이미지가 없는 카드도 있기에 없을 때 처리를 추가 했다.

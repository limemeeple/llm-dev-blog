## 파이썬 코드 컨벤션이과 패키지 관리

코드 컨벤션 <-> 코드 리팩토리(좀 더 고차원)

- **일관되고 읽기 쉽게 작성하기 위한 규칙**
- **들여쓰기, 변수명, 함수명, 공백, 줄 길이, import 순서** 같은 작성 방식을 포함.
- 코드 컨벤션을 지키면 다른 사람이 코드를 **더 쉽게 이해하고 유지보수** 할 수 있음.

### PEP 8 핵심 규칙
- 들여쓰기 : 4칸 사용
- 줄 길이 : 79자 이내 권장
- 공백 규칙 : 연산자 주변, 콤마 뒤 공백
- import 정리 : 표준 -> 서드 파티 -> 로컬
  - 표준 : 설치 안해도 되는 것(파이썬 설치시 기본으로 가지고 있는 것)
  - 서드 파티 : 누군가각 만들고 배포한 라이브러리(설치가 필요)
  - 로컬(local) : 나(팀원)이 만들어서 배포함 라이브러리(파일로 오고 감)
- 빈 줄 사용: 가독성을 위해 적절히 추가.

### 좋은 이름 짓기
[임의로 지정하되 잘 짓도록 하자]
 - 변수명 : 의미가 명확하고 구체적으로
 - 함수명 : 동사 + 목적어 형태로

[꼭 이름을 지켜줘야 함.]
 - 클래스명 : 명사(파스칼 케이스) 사용
 - 상수명 : 대문자 + 언더스코어

- 불리언 변수명 : is/has/can 등으로 시작

[번외]
표기방식에는 '파스칼 표기법', '카멜 표기법', '스네이크 표기법'이 있다.
- 파스칼 표기법 : 가장 앞자리를 대문자로 표기(class/함수 구분 짓기 위해서)
- 카멜 표기법 : 의미가 있는 단어의 첫 글자를 대문자로 표기
- 스네이크 표기법 : 의미가 있는 단어의 구분을 '_' 로 한다.(대소문자 구분을 못하는 언어 환경에서 주로 사용)

- 상수 : 프로그램이 동자고디는 동안 변경되지 않는 값(암호, 인증키 등의 값), 전체 대문자


### 함수 작성 컨벤션
- 한 함수 = 한 역할 : 단일 책임 원칙
- 인자 수 줄이기 : 단순하고 명확하게
- 반환값 명확화 : 예측 간으한 결과 제공
- 중복 제거 : 재사용 가능한 함수 만들기
  - 사용된 코드가 여기저기 함수에서도 발견되는건 좋지 않다.
  - 재사용 가능한 함수를 호출하는 방향으로...
- 테스트 가능성 : 작은 단위로 나누기
  - 덩어리가 커진다? -> 테스트가 오래 걸림-> 문제 발생 위치를 찾기 힘들다.

### 주석과 문서화
- 주석 : 개인 일기장.(내용, 작성자, 날짜)
- 문서화 : 외부로 부여지는 문서.(이 함수는 어떤 의도로 만들었는지, 어떻게 써야 하는지에 대한 설명)
- docstring작성 : 함수/모듈 목적과 사용법
- 공개 함수 문서화 : 외부 사용자를 고려
- 파라미터/반환값 설명 : 타입과 의미 명시

[번외]
- list, tuple, dic <- 자료 구조(값을 담는 주머니 모양)
- int a = 0; <- 데이터 타입(변수의 용도를 지정)
- a:int = 0 <- 타입 힌트(없어도 되지만 어떤 형태가 들어가는지 알려줌)

```
def plus(a:int, b:int): -> int
  """
    함수에 대한 설명, 인자값 설명, 반환값 설명
  """
  return a+b
```

### 타입 힌트
- 기본 타입 : int, float, str, bool
- list/dict : list[T], dict[K, V]
- Optional : Optional[T] 또는 T | None
- 반환 타입 : -> T 로 표현
- 협업 도움 : IDE 지원, 버그 감소


### 예외 처리 컨벤션
- 구체적 예외 사용 : 예외 타입을 명확히
- bare except 지양 : 원인 파악이 어려움
- 예외 메시지 명확화 : 맥락이 드러나게
- 복구 가능한 경우만 처리 : 불필요한 예외 숨김 방지
- 로깅 고려 : 문제 추적과 디버깅에 도움

### AI 코드 작성 시 유의사항
- AI는 대부분의 경우 일반적인 코드 컨벤션을 기반으로 코드를 생성함.
- 반복적인 수정 요청과 기능 확장 과정에서 코드 스타일의 일관성이 점차 저하될 수 있음.
- 따라서 AI가 생성한 코드라도 최종적으로는 **개발자가 코드 컨벤션을 이해하고 검토**할 수 있어야 함.

## uv를 이용한 프로젝트 실행.
1. 프로젝트 생성.

2. uv 설치
```
#uv 설치
pip install uv

#확인
uv pip list
```

3. 현재 프로젝트를 uv로 초기화
```
# uv init --bare
```
pyptoject.toml 파일 생성 된다.
```
[project]
name = "uv-project"
version = "0.1.0"
requires-python = ">=3.14"
dependencies = []
```

4. 패키지(라이브러리) 추가
```
pip install pandas
uv add pandas
```
pyptoject.toml 을 확인 해보면 
```
[project]
name = "uv-project"
version = "0.1.0"
requires-python = ">=3.14"
dependencies = [
    "pandas>=3.0.5",
]
```
추가 되어 있는걸 확인 가능 하다.

#dic:{}, list:[], tuple()

### 프로그래밍이란?
- 컴퓨터와 소통하는 방법을 의미
- 컴퓨터에게 전달하는 정보를 어떻게 보여주고 제어할지 결정 가능
- 웹 개발을 하기 위한 언어로 브라우저와 소통

### 웹사이트 제작시 고려 사항
1. 웹 표준
  - 웹 사이트를 작성할 때 따라야 하는 공식 표준이나 기술 규격.
2. 웹 접근성
  - 장애의 여부와 상관 없이 모두가 웹사이트를 이용할 수 있게 하는 방식.
3. 크로스 브라우징
  - 모든 브라우저 또는 기기에서 사이트가 제대로 작동하도록 하는 기법.
